Play Detach

What it does

The Play Store updates apps on its own, even when auto-update is turned off for them. Play Detach hides the apps you choose from the Play Store, so it never offers or installs updates for them.

The apps themselves are not changed. They keep working, and you can update them by hand at any time.

How to use it

  1. Find the app in User apps or System apps. The search box matches app names and package names.
  2. Turn on the switch next to it. The change applies right away and the Play Store is restarted, no reboot needed.
  3. The Detached tab lists every detached app. Turn a switch off to let the Play Store see that app again.

Apps marked Not installed are still on your list but no longer on the phone. Turn them off to remove them from the list.

Status line

  • Active in Play Store - the module is working in the Play Store.
  • Applies when the Play Store opens - the list is saved; open the Play Store once to load it.
  • Problem - the module could not start in the Play Store. The message shows the reason; see Troubleshooting below.

Command line

Everything in this page can also be done from a terminal with root. In Termux the short command play-detach is installed as well.

Show detached apps
su -c '/data/adb/modules/play-detach/play-detach list'
Detach one or more apps
su -c '/data/adb/modules/play-detach/play-detach add com.example.app'
Re-attach an app
su -c '/data/adb/modules/play-detach/play-detach remove com.example.app'
Re-attach everything
su -c '/data/adb/modules/play-detach/play-detach clear'
All commands
su -c '/data/adb/modules/play-detach/play-detach help'

Detach apps at install time

Put a file named detach.txt in the root of the module zip, with one package name per line. The apps in it are detached while the module installs. Lines starting with # are ignored.

How it works

Play Detach is a Zygisk module. It loads only into the Play Store process. When the Play Store asks the system whether a detached app is installed, the module changes that request, so the system answers that the app does not exist.

The list is stored in /data/adb/play-detach/detach.list, one package per line. Nothing outside the Play Store is touched.

Requirements

  • arm64 device with Android 10 or newer
  • A working Zygisk: ReZygisk, Zygisk Next or NeoZygisk on KernelSU, SukiSU-Ultra or APatch, or Zygisk enabled in Magisk
  • Do not install it together with zygisk-detach, both modules change the same Play Store calls

Troubleshooting

If an app still shows up in the Play Store, close the Play Store, clear its cache in system settings and open it again. Then check the module log:

su -c 'logcat -d -s PlayDetach'

A line with active in Play Store means the module works. Any other message names the step that failed, for example a missing Zygisk or a change in a new Android version.

How it is built

  • Zygisk library - C++20, built with Android NDK r29 for arm64-v8a. Uses Zygisk API v4, so it runs on ReZygisk, Zygisk Next, NeoZygisk and Magisk. No third-party libraries. Every read from Play Store binder data is bounds-checked, and on anything unexpected the call is passed through untouched.
  • Command line tool - a plain shell script. The list is written to a temporary file and then swapped in, so the Play Store never reads a half-written list.
  • WebUI - plain HTML, CSS and JavaScript with no frameworks and no build step. App names and icons come from the root manager's WebUI API. Fonts are bundled, so it works offline.
  • Build - one build.sh script builds the whole module from source.

Tested on

Poco F6 Pro with the Xiaomi.eu ROM (Android 16), SukiSU-Ultra and ReZygisk. Other devices should work but were not tested.
